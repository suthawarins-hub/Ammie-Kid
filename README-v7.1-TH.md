# Pregnant Manager Pro v7.1 — PIN-first + Passkey

## สิ่งที่เปลี่ยน

- เปิดแอปครั้งถัดไปเมื่อ Supabase session ยังใช้งานได้: เลือกคุณแม่เอมมี่ / คุณพ่ออาร์ → ใส่ PIN 6 หลัก ไม่ต้องกรอกอีเมลใหม่
- ถ้าไม่เคยตั้ง PIN สำหรับโปรไฟล์นั้นบนอุปกรณ์นี้: ตั้งรหัสและยืนยันอีกครั้ง จากนั้นใช้งานได้
- ถ้าไม่มีเซสชันหรือเปลี่ยนโทรศัพท์: เข้าด้วย **Passkey** ได้เมื่อเปิดใช้งานใน Supabase และบัญชีลงทะเบียน Passkey สำเร็จแล้ว; หรือใช้อีเมล/รหัสผ่านสำรอง
- มีปุ่ม `เพิ่ม Passkey` ใน **Settings → PIN & โปรไฟล์** สำหรับบัญชีที่ล็อกอินแล้ว
- ใส่ PIN ผ่านแป้นกดในหน้าเว็บหรือแป้นตัวเลขของโทรศัพท์ได้
- ตรวจรหัสไม่ถูกต้อง 5 ครั้งจะพักการลองชั่วคราว และบันทึกสถานะการพักบนอุปกรณ์ (เป็น deterrent ไม่ใช่ rate limit แบบเซิร์ฟเวอร์)
- PIN เก็บเฉพาะค่าแฮช PBKDF2 SHA-256 พร้อม salt เฉพาะรหัสและรอบแฮช 310,000 รอบ; รองรับรหัสจาก v7 เดิมและอัปเกรดเมื่อปลดล็อกสำเร็จ
- ลืม PIN: ต้องออกจากเซสชันและยืนยันบัญชีด้วย Passkey หรืออีเมล/รหัสผ่าน **ก่อน** รีเซ็ต PIN เดิม
- แอปล็อกเมื่อไม่ได้ใช้งาน 20 นาทีหรือกลับมาจากพื้นหลังหลัง 5 นาที

**หมายเหตุด้านความปลอดภัย:** PIN 6 หลักเป็นตัวล็อก UI บนอุปกรณ์ที่มี session Supabase ใช้งานได้เท่านั้น ไม่ใช่การลงชื่อเข้าใช้กับ Supabase และไม่สามารถปกป้องข้อมูลจากผู้ควบคุมเบราว์เซอร์/โปรไฟล์นั้นได้เทียบเท่า Passkey. ทั้งสองโปรไฟล์ใน PIN screen เป็นโหมดแสดงผลและทางลัด ไม่ได้แยกสิทธิ์บัญชี Supabase จริง. หากต้องการบัญชีแม่และพ่อที่แยกสิทธิ์แต่แชร์ข้อมูลในครอบครัว ต้องใช้บัญชี Supabase Auth แยกกัน และเชิญเข้าครอบครัวเดียวกัน.

## เปิด Passkey ใน Supabase (ต้องทำก่อนใช้ปุ่ม Passkey)

1. เข้าโปรเจกต์ของคุณใน Supabase Dashboard → **Authentication → Passkeys** → เปิด **Enable Passkey authentication**
2. ตั้ง **Relying Party Display Name** เป็น `Pregnant Manager Pro`
3. ตั้ง **Relying Party ID** เป็น hostname ของเว็บไซต์ที่ติดตั้งจริง โดย **ไม่ใส่** `https://` หรือ path ตัวอย่าง GitHub Pages `username.github.io` (แทน `username` ด้วยชื่อบัญชี GitHub ของคุณ)
4. ตั้ง **Relying Party Origins** เป็น origin HTTPS เช่น `https://username.github.io` โดย **ไม่ใส่ path** `/my-repo/`
5. เปิดเว็บไซต์จริงผ่าน GitHub Pages ด้วย HTTPS → เข้าระบบด้วยอีเมลเดิมครั้งหนึ่ง → Settings → PIN & โปรไฟล์ → **เพิ่ม Passkey** → ยืนยันตามขั้นตอนระบบอุปกรณ์
6. ทดสอบออกจากระบบ แล้วใช้ปุ่ม **เข้าสู่ระบบด้วย Passkey**. หากเลือกบัญชีผิดหรือ Passkey ไม่พร้อม ใช้อีเมลเดิมเป็นทางสำรอง

**ควรใช้ domain ถาวรตั้งแต่ต้น** เพราะเปลี่ยน Relying Party ID ภายหลังจะทำให้ Passkey เดิมใช้ไม่ได้จนกว่าจะลงทะเบียนใหม่. ฟีเจอร์ Passkey ของ Supabase เป็น **Experimental** ในช่วงที่จัดทำ.

## GitHub Pages / PWA

- อัปโหลด **ไฟล์และโฟลเดอร์ที่อยู่ใน ZIP ทั้งหมด** ไว้ใน root ของ repo ที่ใช้ GitHub Pages (รวม `access-v7.1.css`, `app.js`, `index.html`, `sw.js` และไฟล์ assets)
- ระบบ Supabase URL + publishable key ยังใช้โปรเจกต์เดิมใน `config.js`, **ไม่ต้องรัน SQL ใหม่สำหรับงาน PIN/Passkey**
- หากหน้าเว็บค้างเวอร์ชันเดิม ให้เปิดออนไลน์ อัปเดต PWA หรือทำ hard refresh ก่อน; Service Worker ถูกเปลี่ยนเป็น cache `v7-1` แล้ว
- ถ้าโปรเจกต์ v7 ยังติดตั้ง SQL ไม่สำเร็จ ให้แก้ไขฟังก์ชันเดิมและทดสอบ RLS ก่อนบันทึกข้อมูลจริง — UI สำหรับ PIN/Passkey ไม่แก้ไขปัญหาฐานข้อมูลเดิม
- ไม่มีการเพิ่ม server-side Python, API secret หรือ service_role key ในไฟล์เว็บ

## ทดสอบ

- โหมดจำลอง: PIN ตั้งครั้งแรก, กรอก PIN ใหม่, ปลดล็อก, เปลี่ยนหน้าระบบ, กรอกชื่อเล่นอังกฤษและอัลบั้มรูปคุณแม่
- Mock Auth: `signInWithPasskey`, `registerPasskey` และตั้ง/ปลด PIN หลัง sign-in รวมทั้งกดรีเซ็ต PIN
- ยัง **ไม่ได้ทดสอบ Passkey กับ Supabase จริง** และไม่ได้ทดลองบน Face ID/iPhone/Android จริง เนื่องจากต้องเปิด Passkeys ใน Dashboard ของเจ้าของโปรเจกต์และยืนยันด้วยอุปกรณ์

อ่านเพิ่มเติม: https://supabase.com/docs/guides/auth/passkeys
